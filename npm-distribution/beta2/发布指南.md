# beta2 手把手发布指南

本地文件已准备好。下面的网页发布和 npm 发布需要你登录自己的账户完成；目前尚未上传或发布 beta2。

新版发布号统一为 **0.12.11-beta.2**，GitHub 标签为 **v0.12.11-beta.2**。原有成长功能版本和用户数据目录仍使用 0.12.10。旧版已发布文件保持原样。

## 1. 更新 GitHub 源码与首页

1. 用文件资源管理器打开：
   D:\Xiaorui Wang\AI+竞赛资料\v0.12.10\npm-distribution\beta2\github-upload
2. 打开 https://github.com/SpaceFlight999/ai4edu-MIMIR ，确认在 main 分支。
3. 点击文件列表上方 **Add file → Upload files**。
4. 进入本地 github-upload 文件夹，选中里面的 **README.md 文件** 和 **npm-distribution 文件夹**，一起拖到网页上传区域。不要拖最外层 github-upload 文件夹。
5. 检查上传路径：README.md 应在仓库根目录；其余文件应在 npm-distribution/beta2/ 内。这个目录不包含巨大运行包、用户资料或模型密钥。
6. 提交说明填写：Update beta2 installer, documentation and desktop shortcut。
7. 点击 **Commit changes**，如出现确认窗口再次提交。刷新仓库，确认首页显示新版安装命令。

如果 GitHub 提示浏览器不能上传文件夹，可先单独上传 README.md；然后在仓库用 Add file → Create new file，文件名填写 npm-distribution/beta2/.gitkeep，提交后进入 beta2，再使用 Upload files 上传本地 github-upload/npm-distribution/beta2 中的文件和 package 文件夹。不要将源码 ZIP 直接上传后期待 GitHub 自动解压。

## 2. 创建 GitHub Release，上传完整运行包

1. 打开 https://github.com/SpaceFlight999/ai4edu-MIMIR/releases/new 。
2. 在 Tag 中输入 **v0.12.11-beta.2**，选择创建新标签，Target 选 **main**。
3. Release title 填 **MIMIR 0.12.11-beta.2**。
4. 用记事本打开 beta2 文件夹里的 **Release说明.md**，复制正文到 Description。
5. 在正文下方的 **Attach binaries by dropping them here or selecting them** 附件区域上传：
   beta2\release\MIMIR-0.12.11-beta.2-Windows-x64.zip
   beta2\release\MIMIR-0.12.11-beta.2-Windows-x64.zip.sha256
   请使用 Release 二进制附件区域，不要使用 Description 编辑框的回形针，也不要传到普通仓库文件列表。
6. ZIP 约 938 MiB，等待两个附件上传完成，不要改 ZIP 文件名。
7. Release label 选 **Pre-release**，如有 Set as latest release 不勾选，然后点击 **Publish release**。
8. 发布后在 Assets 中确认能看到上面两个完整文件名。GitHub 自动生成的 Source code.zip 不是完整运行包。

运行包的下载地址必须与 npm-distribution/beta2/package/release.json 中的 url 完全一致。包内已经固定 SHA-256；不要修改 ZIP 后仍使用旧 release.json。

## 3. 发布 npm 安装器

在 PowerShell 依次执行，每条执行完再执行下一条：

```powershell
Set-Location -LiteralPath 'D:\Xiaorui Wang\AI+竞赛资料\v0.12.10\npm-distribution\beta2\package'
npm.cmd whoami --registry=https://registry.npmjs.org/
```

应显示 **spaceflight99**。如提示未登录，再执行以下命令并完成浏览器登录：

```powershell
npm.cmd login --registry=https://registry.npmjs.org/
```

确认 GitHub Release 已公开且附件上传完毕后，执行：

```powershell
npm.cmd publish --access public --tag beta --registry=https://registry.npmjs.org/
```

如提示 Press ENTER to open in the browser，按回车并在浏览器完成身份验证。只有看到 **+ @spaceflight99/mimir@0.12.11-beta.2** 才表示发布成功。npm 可能需要几分钟处理。

这次使用 beta 标签，原来的 latest 保持不变。发布同一个版本号成功后不能再覆盖；若后续还要改内容，需要使用新版本号重新发布。不要因为等待处理而立刻再次发布同一个版本。

## 4. 核对公开版本并体验

```powershell
npm.cmd view @spaceflight99/mimir@0.12.11-beta.2 version --registry=https://registry.npmjs.org/
npx.cmd --registry=https://registry.npmjs.org/ @spaceflight99/mimir@0.12.11-beta.2 --version
```

两条均应显示 **0.12.11-beta.2**。然后从托盘退出旧 MIMIR，再执行：

```powershell
npx.cmd --registry=https://registry.npmjs.org/ @spaceflight99/mimir@0.12.11-beta.2
```

等待安装完成，确认桌面出现使用双线 M 图标的 **MIMIR** 快捷方式、网页能正常打开、旧资料仍在。测试长路径修复时，请让原来安装失败的那台电脑使用这条新命令；旧的 @0.12.10 命令仍然是旧安装器。

新版程序目录：%LOCALAPPDATA%\MIMIR-Evaluation\versions\b2-1171b80c6d40\runtime
资料目录：%LOCALAPPDATA%\MIMIR-Evaluation\data\0.12.10

使用 --install-only 也会创建快捷方式，只是不立即启动。快捷方式指向本机程序和现有资料目录，不需要每次下载。首次安装用户仍需安装 Node.js 24 或更新版本。

发布成功后，对外提供上面的新 npx.cmd 命令和 GitHub 首页链接即可。
