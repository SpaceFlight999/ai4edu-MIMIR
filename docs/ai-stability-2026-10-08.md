# AI 耗时、失败提示与稳定性改进

## 现有调用中确认的问题

代码检查发现成长 Agent 和文稿 AI 原本使用120秒的整次时限，包含多轮工具调用、模型生成与原生重试；原生 DeepSeek 的空闲等待可达300秒，默认请求重试最多五次，外层可能提前中止。论文导读和跨论文研究原本只有180秒整次时限，较长原文需要多个分段分析，并可能再合并、复核，最多约六次串行调用共用这个预算。

原成长层把超时与主动取消合为同一报错；论文层把多种供应商错误转为笼统失败，并在轮询时丢失机器错误码。大量补充、成果和工作台记录还可能不断扩大成长请求的上下文。这些是可确认的失败因素；本机现有记录没有提供用户那次失败的明确错误码，不能断言具体是超时、网络、Key或额度问题。

## 本轮修复

- 成长 Agent 整次预算改为5分钟，保持工具数量、推演步数与输出大小边界，主动取消和超时分别处理。
- 论文导读整次预算改为10分钟，单次模型调用最多5分钟。超过时限明确显示超时，保留原文、笔记和此前成果；不会把半成品当成成功结果。
- 文稿正文建议与各工具板块的 AI 协作改为5分钟时限；论文研究工作流总预算改为10分钟，仍保持输入、输出和授权页范围校验。
- 成长请求中的旧学习、成果、竞赛工作台提供有限摘要，并明确注明未提供全文；不修改已保存内容。发送前设置200,000字符上限，过大时在发起模型请求前提示精简范围。
- 区分凭据拒绝、限流／额度、供应商故障、连接中断、上下文过大、输出截断与响应格式不完整。上游原始错误文本不直接进入本地任务错误响应，防止泄露内部连接信息。
- 原研究聊天复用原生时钟，显示“MIMIR 已处理…”和处理用时；每轮失败保留提示，原生重试详情默认展开并显示错误码。
- 成长方案、交流、评价等处理中显示递增秒数。论文生成与提问同样显示耗时，失败显示可见警报和错误码。
- 文稿 AI 协作通过同源两个 AI 接口显示耗时，网络或 HTTP 失败在浮层逐次提醒；原模块内的详细错误提示继续有效。包装不读取正文或凭据，不修改请求及响应，不自动应用生成建议。多任务并发时显示任务数和最长等待时间。
- 论文研究子面板显示运行任务累计耗时，失败消息带警报角色；历史列表读取失败不阻止接通新任务的状态跟踪。
- 论文状态读取短暂断线时只重连状态，不重新发送模型请求；连续失败后提供重新读取入口，并保留取消操作。取消后重新读取终态并清理计时与禁用状态。
- 错误分类兼容 DSH 把 HTTP 状态存入 `failure.status` 的异常，避免供应商503和输入413被误归为普通失败。计时器在完成、失败、取消、切换任务及模块卸载时清理。

## 再发生失败时怎样处理

| 提示 | 下一步 |
| --- | --- |
| MODEL_TIMEOUT | 改用选区或章节，拆分目标；在原模型设置选择响应更快的可用模型。 |
| MODEL_CONTEXT_LIMIT | 减少本次资料和目标，按章节分段处理。 |
| MODEL_AUTH | 核对供应商、所选模型与该供应商的 API Key。 |
| MODEL_RATE_LIMIT | 检查账户额度或服务限流，稍后手动重试。 |
| MODEL_NETWORK／MODEL_PROVIDER_ERROR | 检查网络、代理与供应商地址，或稍后重试。 |
| MODEL_OUTPUT_LIMIT／MODEL_RESPONSE_INCOMPLETE | 缩小输出目标或分段提问；已有保存内容保留。 |
| 状态读取失败 | 重新读取任务状态；不要重复发起相同任务，也可取消。 |

这些改动改善等待和诊断，不承诺消除供应商自身故障。所有验收使用隔离合成资料、本机受控模型和实际 DSH／PDF 解析链路，未用个人Key或付费在线调用。字体放大与右对齐按用户最新要求暂缓。

高亮补充要求已实现：可取消选区覆盖的已保存高亮，无高亮时不删除其他笔记；重复高亮已覆盖区域不新建相同记录，已有重叠标记以同一透明度合成，不因叠加加深颜色。
