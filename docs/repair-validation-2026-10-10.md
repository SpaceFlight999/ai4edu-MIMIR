## 模型路由与凭据

所有在线 AI 选择统一为 `deepseek-official / deepseek-flash`，使用官方原生 `https://api.deepseek.com/anthropic/v1/messages`。官方产品名称为 DeepSeek V4.1 Flash；旧别名仅迁移到规范 ID，不凭旧 UI 标签判断实际请求。

模型策略覆盖当前选择、保存选择、普通流、预备调用及会话标题。生产端点固定官方 HTTPS；仅 `NODE_ENV=test` 下允许回环模拟服务。绕开原生配置的非官方地址在发出请求前拒绝。合法思考强度 off/low/high/max 保留；新 home 默认 off。策略保持原生调用的取消、上下文、prepared agent 与返回事件契约。会话标题只修改解析路由，其余上游行为保留。

配置或端点违规返回固定安全中文说明。凭据仍由本机原生服务存储。验收 Key 仅在当前用户加密文件和短暂进程环境/stdin 中使用；不写入源码、Git、报告、交付包或请求日志。每轮在线验收清除独立 home 的凭据载体。新设备需首次配置自己的官方 Key，交付包不复用他人的凭据。

官方依据：[模型列表与调用说明](https://api-docs.deepseek.com/quick_start/pricing)、[Anthropic API 兼容接口](https://api-docs.deepseek.com/guides/anthropic_api)、[更新记录](https://api-docs.deepseek.com/updates)。本机实际响应模型及路由以本轮 `deepseek-live`、`live-growth`、`live-native` JSON 为证。

## 内部输出规范

成长方案只围绕学生目标、基础、深度和可用时间做取舍；双周 tasks 只用 week 1/2，远期目标写入 roadmap。具体任务有操作、材料和可检查成果。时间说明从最终任务相加，不虚构“已掌握”；资源目录规范化补入基础任务时应解释实际范围。成果评价只按既有 criteria；新例题先由学生预测，再使用已有数值工具核对，不能临时提高完成标准。

论文与研究严格区分原文作者陈述、系统解释、外部知识与研究建议。缺少数据、全文或可比条件时写明本次材料不足，不将“未提供”当成“作者没做”。逐字引用、source/version/page 仍校验；综合写作经过分析、引用校验、综合与复核，不直接发布。写作保留理想化、仿真/实物、范围及否定等限定；说明只描述实际 patch，不能臆造语法或事实改善。

检索摘要只概括给定摘要和来源，不能把预印本或提交时间当作质量排名。工作台脚本只提供建议，执行和写入仍需原用户流程。内部提示收紧经过本地回归；模型仍可能生成结构合法但事实错误的内容。

本轮使用 **agent-reach** 与 **research** 技能联网核对原始教材、MIT 课程范围、CMU 评价指导、arXiv 元数据、Purdue 写作指导、NIST 模型验证及 ICMJE 引用原则。两份来源文档列出来源、支持范围与实际纠错：[成长与数值审核](ai-quality-sources-2026-10-10.md)、[写作与研究审核](ai-writing-research-quality-sources-2026-10-10.md)。ICMJE 仅用于通用证据审核，不强加医学论文格式。

规则已进入 `model.mjs`、`dsh-agent.mjs` 及原生后端 `index.js`、`unified.js` 的实际提示构造。数值工具说明明确坐标系、相对角、单位和原预测；成果反馈只按原标准；规范化任务范围与工时一致。写作保留限定，引用核对指标/单位/条件/否定；arXiv 期刊引用与 DOI 提供线索，不一概判未评审，也不认证研究质量；少量共线点或高 R² 不替代验证。现有 Agent 未新增网络工具，不会假称每次回答已自动联网。

## 真实输出的已知不足

成长六入口均已接通实际官方模型并通过后台结构校验，累计 10 次请求。人工阅读仍发现评价标准越界、角度算例新坐标错误、复盘时间叙述矛盾、规范化基础任务与方案理由不一致。导入第一次将远期周次写进双周 tasks，后台拒绝且状态未改变；单独修正重测后通过。详见 `docs/ai-growth-hardening-2026-10-10.md` 与全部尝试 JSON。

原生首轮 11 次请求均返回规范模型。导读因不合法类别被拒绝，未保存未经校验的结果；其后综合写作因缺少导读拒绝。Word 建议删除理想化限定，Markdown 说明误称去掉被动语态。这些属于语义质量不足，虽未自动改文件仍须记录。随后收紧确切 JSON 类别、限定保留及真实改动说明；已通过的入口未为取得更好样本重复付费。最后部分提示未再次在线验证。

补充尝试中导读通过；单篇综合写作仍因模型制造跨论文比较触发范围保护。之后按实际选中论文数为综合/修复提示明确 `comparisons: []`，不放宽来源保护。所有尝试的实际模型请求与失败均合并保留。初期另有 2 次 HTTP 200 的诊断请求因观察器失败缺少完整模型元数据，不计为成功入口，可能产生官方费用，单列诊断报告。

综合写作一次后续复核拦下引用错配、范围扩大等问题，但修复响应不是有效 JSON。随后将修复阶段的未定义结构别名展开为完整分析/综合字段，并明确 JSON 转义；有明确契约修正后仅重测剩余入口。最终综合写作完成分析、综合、复核、一次修复及再复核；保留 6 项未解决疑点，包括将元信息当成正文原事实、过宽引用和重复。任务完成不等于科学结论已验收。研究聊天的零角 `(2,0)` 正确，但超出 120 字要求，称单位必须为度且补入未提供的摩擦/重力条件；零弧度也对应同一几何结果。两类人工不足写入 `live-native-quality-20261010.json`，`manualQualityPassed:false` 保留。

## 使用与复测

1. 将 `MIMIR-0.12.8-Windows-x64.zip` 解压到可写目录，运行 `Start MIMIR.cmd`；首次在模型设置配置官方 Key。`MIMIR-0.12.8-source.zip` 仅含可编辑维护文件，单独不能启动；使用完整运行包中的同一套源码维护即可。
2. 先在新空 home 体验，不把测试目录覆盖到既有 data。迁移原用户数据需单独备份并沿用原用户身份。
3. 修改后端后运行 `Install MIMIR.cmd`，再重启已运行的宿主；不会自动替换正在运行的上下文。
4. 本地回归可执行 `scripts/check-unit-tests.mjs`、`scripts/check-installed-growth.mjs`、`scripts/verify-runtime.mjs`、`scripts/verify-user-loop.mjs`。在线验收脚本必须显式 `--live` 与临时 Key；会产生官方计费，请不要当成离线安装步骤。
5. 使用 AI 教学、写作和研究结果时，检查原 criteria、单位/角度、原文证据及应用范围。对于本次已记录的数值错误，优先使用既有数值工具与手算复核。
