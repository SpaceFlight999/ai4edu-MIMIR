# MIMIR 产品自查与下一轮迭代依据

日期：2026-10-05。对象：当前 0.4.0 源码、既有交互验收报告与截图、用户最初及后续产品要求。本文记录已确认的问题和待验证的设计假设；没有进行新的真实学生试用。学校与百炼接入暂缓，后续功能设计应先能在无模型凭据时使用。

当前判断：入口、配置、候选确认、学习记录和历史保存已有基础；个性化任务安排、真实学习内容及跨模块联动还不足以支撑长期使用。既有测试证明特定操作可执行、数据可保存，不能证明培养方案适合学生或改善学习效果。

## 与原计划逐项对照

| 用户要求 | 当前证据 | 差距与影响 |
| --- | --- | --- |
| 智慧之泉大入口，选项优先，分步确认 / 回退 | 已有六步配置、预览页与四个功能入口 | 专业、年级、目标和基础默认填好，初次配置容易一路确认示范画像；不能把默认值当成真实诊断 |
| 四方向配比与不同目标深度 | 配比总计 100%，深度分入门 / 应用 / 深入，时间预算有校验 | 配比主要影响示例任务时长；深度主要追加文字标准。缺少调配后“多做什么、少做什么”的可见试演 |
| 核心 Agent 自主定制培养方案 | 有模型提示词、输出校验与候选确认接口；真实模型质量未验收 | 无凭据时只有规则示例；即使接模型，也只能选当前四个注册任务资源，难以覆盖不同学生的实际课程 / 比赛目标 |
| 阶段方案随互动迭代 | 目的追问、卡点记录、复盘与历史已实现 | 本地复盘再次使用同一模板；够用 / 深耕 / 求助没有完整转成具体任务增删、降级、补基础与迁移安排 |
| 可交互待办与当前知识拓扑 | 世界树 12 个教学概念、清单、自查、卡点与下一步 | 课程图谱另外有 8 个概念，自评 / 练习未与世界树统一；相关任务完成状态不等于逐概念掌握 |
| 公开课和配套问答 | 4 门官方课程链接，共 8 道原创选择题 | “先学哪一段”仍较宽泛；无章节进度、诊断分支、错题重练、中文替代资源或迁移题 |
| 比赛推荐、历年题与工作台 | 3 个赛事，4 个历史题 / 规则入口，分步草稿与报告导出 | 缺少按学段、基础、队伍和器材条件的筛选；工作台主要是文字表单，尚无题型专用工具和真正的测试记录结构 |
| 联网近期研究 Top N 与汇总 | arXiv 4 个固定方向，Top 5 / 10、日期与来源；摘要模型概览接口 | 无模型时主要是英文摘要；没有个人收藏、阅读队列、难度 / 相关性解释及独立的研究比较笔记 |
| 兴趣探索与偏好发现 | 方向入口、场景选择、信息分类与小实验问题 | 不同方向进入同一通用探索工作坊；选择方向没有充分改变任务，也没有把偏好形成可解释的成长建议 |
| 同好论坛与方案共享 Star | 森林双入口、模板导入 / 导出、本地 Star、两个示例话题的本地回复 | 不是多用户社区；用户不能创建新话题。收藏不能表示真实热度，共享方案缺少适用基础、条件和学习者经验 |
| 沿神话故事线命名且便于找到 | 智慧之泉、世界树、诺伦回望、密米尔之林均有入口 | 成长导航和原科研空间同时出现，可能形成两套产品心智；需要说明原论文 / 文稿工具服务于哪个当前目标 |

## 源码确认的核心问题

1. **本地方案重复，尚未形成连续培养。** `growth/src/domain.mjs:78` 的 `templatePlan(profile)` 每个方向取第一个资源，两周复用同一资源；`growth/src/host.mjs:83` 的本地复盘仍调用它。合成输入将专业改为数学、基础改为没有编程经验、约束改为次日考试，得到的资源组合与标题仍是机器人产线示例。相同画像再次生成输出相同，全部示例任务前置依赖为空。这是模板模式的局限，不代表已测试真实模型行为。
2. **内容与目标可能错误关联。** `growth/client/app.js:223` 的 `attachLearning` 仅按方向选第一个未完成任务，再拼接成果文字。线性代数练习可能进入二连杆目标；视觉测量赛题报告可能进入 PLC 分拣工作坊。没有结构化的课程 / 题目 / 论文引用，没有目标选择与适配检查。
3. **时间选择没有兑现。** `growth/client/learning.js:74` 让用户选择 10 / 20 / 40 分钟，但之后仍是同样的三步实践。分钟数是保存的本次安排，不是实测耗时，也不会产生不同的小目标。
4. **反馈被记住，尚未充分转为行动。** `growth/src/learning.mjs:68` 保存目的选择到反馈；回望显示这些记录，深耕会建议调整方向深度。但缺少“这次到底改了哪几个任务”的候选差异展示，以及够用后的投入转移、求助后的补基础任务。
5. **两张知识图的数据没有贯通。** `growth/src/catalog.mjs` 的阶段概念按任务资源关联；`growth/src/library.mjs:4` 的课程概念另有 ID。`growth/src/journey.mjs:25` 汇总相关任务状态给节点着色，课程练习结果不按具体概念形成证据。
6. **改计划后需要重新寻找未完成工作。** `growth/src/domain.mjs:116` 确认候选将旧方案整体转为历史，新方案任务有新 ID。旧成果保留，但没有同一学习单元的明确延续、未完成任务迁移与成果沿用建议。
7. **持久化边界不够可见。** 页面内未保存草稿多在 `memory` 中，刷新会丢失；显式保存才写数据库。目录入口切换会重建内容页，研究联网结果若未生成并保存概览没有长期收藏记录。缺少一致的未保存提示与恢复入口。
8. **错误信息妨碍自助恢复。** 当前 JSON 解析失败统一显示“连接暂不可用”。此前实际诊断发现新版 `/library` 在旧后端返回 404。应区分旧后台、登录失效、网络失败、模型缺失，并在界面给出下一步。

## 从学生视角提出的设计假设

以下是假设，需要用任务操作观察验证，不把它们当作已证实的需求。

| 学生的处境 | 可尝试的交互 | 验收方式 |
| --- | --- | --- |
| “昨天做一半，今天从哪继续？” | 有方案后首页主入口显示“继续上次学习”，保留重新配置为次入口；显示上次保存的小步 | 再次启动，一次点击回到保存步骤，草稿与来源仍在 |
| “我只有十分钟，不想打开一串表单。” | 时间选择实际裁剪本次动作：10 分钟做一个判断，20 分钟练一轮，40 分钟比较并整理 | 三种时间下可见小目标不同，保存后仍能继续完整任务 |
| “任务太难，但我不想重做整份计划。” | 在目标内选择补先修、换同目标材料、拆小步、延期；只预览受影响部分 | 原计划有效，确认差异后才更新；不丢已有成果 |
| “我说够用了，为什么还给我同样的题？” | 目的回答形成一张调整建议卡：保留成果、停止哪类重复练习、投入转给哪里及原因 | 下一候选不无理由重复同一学习单元，改动与回答可对照 |
| “两周都没打开，是不是已经失败了？” | 返回时提供“接着做 / 减轻负担 / 重排本周”三个选项，解释过期任务 | 可处理未完成任务并保留历史，不要求假装完成或从头配置 |
| “我不会英文，也不知道该选哪门课。” | 推荐理由、最低先修、小段内容和可选替代材料；无模型也有人工编写的中文导学 | 初学者能选择材料并开始具体一段，不只得到整门课链接 |
| “我完成了很多东西，究竟留下了什么？” | 成果架汇集阅读卡、练习解释、项目报告、验证记录，标出来源、阶段和待补内容 | 能按来源 / 方向打开真实成果并导出；不把次数换成能力分数 |
| “这篇新论文与我有什么关系？” | 论文加入阅读队列；显示能帮助的当前问题、先修和阅读目标；提供问题 / 方法 / 证据比较表 | 所有条目可追溯，比较内容来自用户笔记或明确的模型推断 |
| “选一个兴趣方向不等于愿意一直学它。” | 两三次短体验后让用户比较喜欢、费劲和想继续验证的部分；允许选不确定或暂停 | 偏好能解释来源，不从一次点击推断长期职业或科研方向 |
| “别人的路径能不能适合我？” | 共享方案展示学段、基础、时间、资源条件；导入前比较与自己差异 | 前置依赖仍有效，预算适配可解释，不直接复制别人进度 |

## 下一轮实施顺序

### 第一批：先把培养闭环做实

1. **来源与任务绑定。** 引入课程、赛题、论文等明确引用；带入时选择已有兼容目标或形成新增目标候选。标题、完成标准和工作坊必须对应来源，不能只按四方向附加文字。
2. **本地阶段决策。** 在机器人示范范围内，根据基础、目标类型、已完成单元和够用 / 深耕 / 求助选择，生成下一步候选。说明是规则建议，保留未来模型适配位置。两周内容体现诊断、应用和验证的递进。
3. **计划差异与延续。** 预览保留 / 调整 / 新增 / 延后项及理由；选择是否继续未完成任务。正式确认保留旧版本，并让用户找到继续进行的成果。
4. **继续学习与保存恢复。** 首页根据是否已有方案显示适当主入口，保存状态明确，刷新能恢复已保存步骤，未保存离开有提醒；错误提示能够区分原因。

第一批完成标准：无模型账号的学生能配置真实偏好，完成一个具体学习单元，选择够用 / 深耕 / 求助，看到对应且不重复的下一阶段差异，确认后继续；外部课程 / 题目 / 论文不能落到错误的工作坊。

### 第二批：每个方向做出实质内容

5. **学习。** 统一概念 ID 和证据关联；节点提供一段导学、针对性题目、提示、错题重练与迁移任务。两道选择题不能承担完整课程诊断。
6. **竞赛。** 按本科 / 专科、基础、队伍与设备条件选方向；先做一个题型专用工作台，包括条件清单、方案结构、测试用例及实际结果表。代码执行和硬件仿真另行评估，不用通用表单冒充执行环境。
7. **科研。** 阅读队列与保存、来源绑定、问题 / 方法 / 证据卡，逐步与原论文模块的真实材料关联。联网列表和摘要概览不代替论文导读。
8. **兴趣。** 不同方向提供不同短体验，记录偏好及原因，形成可解释的探索建议。
9. **成果。** 统一成果架、回看、搜索和导出，避免在阶段历史的任务里逐项寻找。

第二批完成标准：用户在同一示范方向内有一段可重复使用的学习过程，不必反复填写相同模板；内容推荐、任务、成果和知识节点能够互相打开。

### 第三批：共享与社区

10. 先完善本地的方案适用条件、依赖保留、话题创建和目标相关讨论入口。跨用户 Star、论坛账号、协作队伍及云端同步需要独立的服务设计和数据隔离，不宣称本地演示已满足在线社区要求。

暂不优先：Electron、新神话子模块、大量装饰性图表、任意代码执行和模型训练。神话名称可继续用于已有主入口，避免让用户学习更多导航名称。

## 下一轮应采用的验收任务

1. 初次进入的基础较弱学生，选课程优先和每周 3 小时：能看到基础起点及具体小段学习，时间预算解释清楚。
2. 学生只有 10 分钟：开始一个小步，保存退出，再次进入能继续。
3. 学生保存线性代数练习或视觉测量题报告：目标标题、工作坊及完成标准与来源一致。
4. 完成一个单元后分别选择够用、深耕、求助：三种下一步候选有可解释差异，确认前旧方案不变。
5. 阶段结束但仍有半成品：可以继续、降负担或延期，真实成果和进度仍可找到。
6. 无模型、无网络或旧后台：可用功能明确，错误有恢复动作；不会把示例或缓存说成实时 AI 结果。

这些是待实现及待验证的验收要求，不是当前 0.4.0 已通过的结果。
