# 模型输出截断的统一递归处理

需求：导读、提问等模型 API 遇到“模型达到输出上限，结果不完整”时，先递归缩减输出、重新生成并检查，成功后再输出；缩减仍失败时才报告。

## 修改

- 在原生模型服务共用的 `llm/stream` 边界接入“程序 A”的输出完整性关卡：`growth/overrides/app/model-output-reduction.mjs`。同一服务上的导读、提问、语义复核及修复、工作台 AI 修改与模块协作、学习 Agent、科研对话、标题生成等调用共用此处理。
- 检测输出 token 截断、明确的输出长度错误和文字字符预算超限。拦住本次半截结果，递归重生成；最多额外缩减六次。
- 每次使用同一份完整原问题、历史和原始证据，逐级缩短生成说明与可选条目目标；保留原任务的必填字段、指定主题、逐项核对、事实、数值、条件、单位及不确定性。供应商、模型、思考强度和原请求配置保持一致。
- 只有完整响应才交给原有 JSON、引用、语义及业务规则校验。被丢弃响应中的文字和工具调用不会传给下游执行；正常完整工具调用保持原有事件身份与权限约束。
- 研究写作沿用已有的阶段递归、事件记录和总预算，并显式标记由阶段管理，避免与新关卡叠加重试。
- 段落/LaTeX 修改、模块协作和学习 Agent 分别沿用已有的字符预算。重试共享原任务的取消信号与时限；未传信号的原生调用继续使用其原有时限策略。
- 认证、限流、网络等错误继续按原类别处理。输出缩减耗尽后，论文和学习入口保留安全的 `MODEL_OUTPUT_LIMIT` 分类与明确提示。
- 提示词10中删除生成时间、来源尾部哈希和证据编号的导入清理继续执行，原有结构化证据和工作台接受建议流程保留。
