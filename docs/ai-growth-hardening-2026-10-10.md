# 成长、学习与研究摘要后端自检

日期：2026-10-10。基线：合作伙伴 0.12.7；验收版本：0.12.8。本文记录本轮成长 AI 子模块修复；完整模型接入、包体和其他模块验收由总报告汇总。

## 实际入口与保存边界

- `generate`、`review`、AI 模式 `import` 共用 `planWithModel`：输出候选，现有资源、方向、时间、课程与先修规则通过后才可保存；学生确认后才切换当前方案。
- `feedback` 使用 `feedbackWithModel`：返回中文交流，建议不得声称已修改方案。
- `evidence` 使用 `evidenceWithModel`：逐项对齐任务原有完成标准，保存反馈与成果；不自动标记完成或客观掌握。
- `research-digest` 使用 `researchDigestWithModel`：依据本次实际检索的 arXiv 元数据及摘要片段生成阅读概览。
- 每次调用均使用独立 DSH Agent，保留本次工具允许列表、四步推演、八次工具、输出和五分钟时限。当前模型由公共模型路由提供。
- 模型期间不持有 SQLite 写事务。现有版本检查、请求幂等和提交前取消检查继续控制保存；连接失败、非法输出、超时或取消不得覆盖已保存记录。

## 已复现并修复

1. `parseModelJson(null)` 原来抛出 `TypeError`；评价中的 `checks: [null]` 也会失去明确业务错误。现在返回安全的 `INVALID_MODEL_OUTPUT`。
2. 空白 `summary`、逐项 `feedback`、`nextStep` 原来可通过评价校验并保存。现在拒绝空白、非文字、超长及不符合原标准或状态枚举的输出。
3. 评价原来直接保存整个模型对象，额外的完成状态、掌握分数等未知字段也会进入记录。现在只保存既有 `summary`、`checks`、`nextStep` 字段，逐项仅保留 `criterion`、`status`、`feedback`。
4. 方案模型输出原来只做 JSON 解析，非法嵌套或文本在后续流程才触发通用错误。现在先按现有领域校验检查，再按既有方案字段筛选；资源、时间、方向、课程引用和原先修约束保持有效。模型自带的身份、状态和自定义主题定义不成为权威数据。
5. 研究摘要拒绝未知、遗漏或重复来源、空白和非法条目，保留原 ID 与长度上限。空来源在发起模型前明确报告，不生成虚假概览。
6. DSH 的 `AUTH`、`MISSING_CREDENTIAL`、`INVALID_CREDENTIAL` 原来归入通用不可用错误。现在统一为 `MODEL_AUTH`，保留安全提示，不显示上游异常正文。
7. 成长 AI 课程目录原来遗漏四项已有深入学习专题，课程工具也无法查询本次提供的自定义学习专题。现在目录包含内置专题及当前选择、当前任务或已校验共享模板中使用的自定义专题；工具仅解析本次已提供的定义，仍剥离诊断与练习答案键，不读取其他文件或创建学习记录。
8. AI 适配导入自定义主题时，方案校验优先使用服务端已校验的共享定义；本机相同 ID 的旧定义及模型返回的替换来源不会覆盖该定义。
9. 新增模型政策错误 `MODEL_POLICY`、`MODEL_ENDPOINT_POLICY`、`MODEL_CONFIGURATION` 的固定中文提示，保留准确错误类别。模型选择服务与 Agent 请求均经过安全转换，不显示上游端点、环境变量、用户 Key、异常正文或 cause。

## 内部输出规范

通用教练先依据目标、基础与时间给出具体动作和检验方法。材料支持的事实说明依据；推断说明成立条件；建议说明下一步。未提供的全文、附件、实测或个人补充来源明确保留限制，学生自报、信心和完成标记不能当作客观能力鉴定。

方案要求具体操作、所需材料和可检查成果，解释预算与目标取舍；先修缺口先补基础。即时交流优先回答当前困难，给一个可执行的小步骤，再提出必要的目的与取舍问题。成果评价按原标准顺序检查直接支持，证据不足使用 `needs-work`，下一步包含操作和检查方法。不得临时增加非零角、额外算例或全面掌握要求：已提供的特例经核对满足原标准，应判断为 `supported`；迁移要求仅作为后续建议。资源 `resourceId` 与课程 `courseRef.id` 分属不同目录，课程查询失败不能推断原学习资源不存在。

摘要仅概括实际提供的研究问题、方法和作者报告结果；跨篇归纳保留推断属性。阅读问题针对尚需全文核实的假设、实验条件或适用范围。不得把按提交时间排列的预印本当作质量或影响力排名，不能臆测录用、同行评审或实验效果。

数值结论必须先使用本次已有且适用的数值工具核对输入、单位与结果；无适用工具或尚未核对时，只给符号表达式、代入顺序及可重复的核对步骤。二连杆数值使用 `growth_robotics_check`，保留学生原输入和预测。新练习只给输入、问题与核对方法，不直接提供新的答案坐标。方案 summary/rationale 的工时须按任务 hours 相加；已列入 tasks 的基础单元必须描述为当前安排，不能同时说成未来诊断失败才补的条件性备选。

以上规范接入真实业务调用链中的系统提示及输出校验，没有新增用户流程或修改前端。结构校验能验证字段、标准对齐和状态边界；数值准确、是否提高评价要求、自然语言的工时和课程范围一致性，仍需结合工具结果和内容审查，提示并非自动语义证明。

## 实际 DSH 与官方模型验收

`scripts/verify-live-growth.mjs` 是显式启动的在线验收脚本。必须提供 `--live` 与调用进程临时环境变量 `MIMIR_LIVE_API_KEY`；源码没有凭据。它使用随机独立 home、合成学生及两条明确标识为非真实论文的 arXiv Atom fixture，仅替换文献获取，模型仍由已安装 DSH Agent 实际调用官方 `https://api.deepseek.com/anthropic/v1/messages`。思考关闭；请求与实际响应模型均为 `deepseek-flash`，供应商为 `deepseek-official`。

首轮六入口共 7 次官方请求；成果评价调用工具后产生第二次请求。导入首轮被既有 schema 拒绝，报告 HTTP 422 / `INVALID_MODEL_OUTPUT`，失败前后保存状态一致。原因是远期周次混入双周 tasks。补充明确的 week 1/2 与远期 roadmap 约束后，仅重测导入 1 次并通过。人工阅读发现首轮成果评价混淆资源与课程目录，并给出矛盾的角度解释；补充资源上下文、目录 ID 说明及给定算例的工具核对要求后，仅重测评价，共 2 次官方请求。累计 **10 次**，没有继续增加付费重试。

六入口最终均验证实际官方响应、后台 schema、当前方案未经确认不得切换的边界。**这不等于六入口的教学内容全部准确**。报告把接通/结构、有限自动检查与人工内容审查分开：`transportAndSchemaPassed=true`，`manualQualityPassed=false`。

基于以上真实失败，最后继续收紧内部提示：方案总工时从规范化任务逐项相加，叙述与目录实际范围一致，区分当前安排与诊断后的条件性备选；评价只能使用原 criteria，不临时提高难度；新练习只给输入、问题和核对方法，让学生先预测，不直接给新的答案坐标；其他新数值先用适用工具核对，无工具时给符号核对步骤。最后这些提示变化仅通过语法及本地受控 Agent fixture 回归，真实数值工具另做错误算例回归；**未经再次在线调用验证，不证明模型会完全遵从新提示**；不能声称已消除全部语义错误。现有严格结构拒绝保持不变，没有为通过验收放宽 schema。
