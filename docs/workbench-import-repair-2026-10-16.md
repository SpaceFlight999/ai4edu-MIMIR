# 工作台导入修复与验证（2026-10-16）

## 原因与修复

现有研究记录对应的工作台建议已被拒绝，但研究导入以“任务编号 + 文稿版本”复用提交缓存。再次导入时返回了创建时的 `proposed` 快照，没有核对建议实际已是 `rejected`，因此前端提示成功，工作台却没有待审阅建议。

- `ResearchCore.proposeResearchDraft` 现在读取实际建议状态。待处理提交复用同一条建议；已拒绝或冲突的提交生成新建议，并为这次提交保留幂等；已应用的重试返回真实 `applied` 状态。
- 用只读数据库和真实历史任务回放现有故障路径，确认命中被拒绝缓存后会走新建议创建分支，14 条引用仍完整关联。回放用替代写入函数，不向个人数据库写建议。
- `proposePaperNote` 同样返回实际建议状态，避免普通论文导入的缓存响应误报。

同时修复共同导入逻辑的边界问题：

- 研究草稿原先只允许 20 条引用，现在允许最多 10000 条，并继续逐条验证项目、来源、解析版本、页码与原文。通过索引和每篇论文的缓存避免重复扫描整份证据清单。普通单条论文笔记继续限制 20 条引用、5000 字；研究草稿正文继续限制 400000 字，超限返回具体导入原因。未对 10000 条引用做性能压测。
- 原先必须找到纯文本段落，且会递归选中列表或表格中的最后一个纯文本段落。现在仅在文档最后一个顶层段落适合时追加文字；否则创建 `appendParagraph` 建议，接受后在文档末尾添加新段落，不修改原有富文本、列表、表格及注释。
- 新操作使用现有摘要绑定、版本检查、一次性授权及 SQLite 事务。旧建议表增加默认 `replaceBlockText` 的 `operation_kind` 列；旧建议摘要和幂等指纹保持兼容。
- 工作台客户端兼容追加建议；论文导入核验保存凭据与状态；研究提交期间防重复点击。导入错误提示区分文稿版本、来源范围和内容限制，不再要求用户为导入问题重新生成已完成草稿。
