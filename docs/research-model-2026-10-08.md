# 0.12.2：精简研究输入与模型错误传递

用户要求自行排查“处理未完成，请检查模型设置或连接”的原因，随后要求编写精简输入的代码。

## 已确认的问题

最近两次失败均发生在首次模型调用。原文与证据已经完整装入，第一次调用用时约 38～50 秒，随后记录 `ADAPTER_FAILED`。研究运行层只接收自己的错误类，将模型传输层已经分类且脱敏的错误统一覆盖，导致界面丢失具体原因。旧记录未保存被覆盖的供应商原因，不能从它们确定是输出不足、网络、授权还是容量问题。

最近失败任务包含 59 页、193,743 字符解析正文与 3,088 条证据；完整请求却达到约 195 万字符。原文、引用逐字文本、来源哈希、定位框等重复传输，增加了模型需要处理的内容。此前研究调用还固定使用 8,000 输出 token，与当前 high 思考模式及结构化结果的需求存在冲突风险；这项风险没有冒充已经确认的旧失败原因。

## 精简代码

新增 `growth/overrides/host/model-context.mjs` 的 `compactResearchRequest(request)`，已接入 `ResearchRuntime.call`。

```js
const {payload, restore} = compactResearchRequest(request);
const reply = await model.generate({system, payload, signal});
const result = restore(reply);
// result 继续经过原有引用、来源、格式和比较条件校验。
```

每页原文完整发送一次。证据仅包含短 `citationId`、页码、原文起止位置和可靠性状态；哈希、版本、定位框和逐字证据仍保存在完整本地快照中，用于引用回跳和核对。起止位置采用 JavaScript UTF-16 索引，重复引文尽量依次匹配，保留表情和中文。保留缺页与视觉内容未核实等覆盖说明。

前一阶段的引用和返回结果的引用双向转换；只修改 `evidenceId`、`evidenceIds`、`citationId` 字段，不改正文、问题或标题。未知引用仍原样保留，由原有校验拒绝，不能因精简绕过校验。没有删除任何页面或证据，也没有新增输入字符上限。

同一失败任务在本机精简后的请求为 475,100 字符，相比原 1,945,133 字符减少 75.57%。只计算大小和核对引用，没有发送个人论文。

## 错误和输出处理

模型传输层通过内部可信标记生成的脱敏错误，在研究运行层保留代码和安全中文说明；不盲目信任外部对象的错误文本。包括供应商失败、授权、容量、输出不完整和单次调用超时。模型不存在及思考强度不兼容也有具体提示。

研究调用输出 token 上限改为 32,768，并要求有限数量的论文结论、方法、问题及短草稿；复核只针对实际引用。用户模型和思考强度设置保持原样，15 分钟任务时限、输出字符校验、引用和来源校验继续使用。输出 token 上限不属于已取消的输入预算。
